本次修改（v1.1.1 — 修复「折线 + 状态叠加」点击崩溃）

⑩ 修复 overlay.lua 充电斜纹绘制崩溃（P0 运行期崩溃）
  • 现象：点击主菜单「折线 + 状态叠加」打开叠加视图即崩溃，KOReader 退出；crash.log 报 overlay.lua:78: attempt to perform arithmetic on 'struct Color8' and 'number'。
  • 根因：充电时段斜纹函数 drawHatch(bb, x0, x1, y_top, y_bottom, color) 的调用（第 139 行）漏传首个参数 bb（Blitbuffer 对象）。Lua 实参向左对齐后，bb 收到 number、y_bottom 收到 Blitbuffer.COLOR_GRAY（即 struct Color8），在第 78 行 y_bottom - y_top 处对颜色结构做算术运算 → 崩溃。
  • 修复：调用处补回 bb 首参，参数与签名对齐：
    - drawHatch(tx(history.ts[i]), tx(history.ts[j - 1]), graph_y, graph_y + graph_h, Blitbuffer.COLOR_GRAY)
+ drawHatch(bb, tx(history.ts[i]), tx(history.ts[j - 1]), graph_y, graph_y + graph_h, Blitbuffer.COLOR_GRAY)
  • 校验：LuaJIT loadfile() 编译 overlay.lua 通过（SYNTAX OK）；参数修复后 drawHatch 内部 drawLine(bb, ...) 的 bb 与 color 均取值正确。仍待真机验证（本环境无 KOReader 运行时）。
  • 影响：仅改动 overlay.lua 单处调用与一个版本号；v1.1.0 的叠加视图其余逻辑（休眠浅灰实色块、图例、时间窗联动）不受影响，数据传递路径（onShowOverlay → OverlayWidget）已确认正确。

本次修改（v1.0.4 — 折线观感修复，无新功能）

⑬ 针对折线图观感的两项修复
  • 充放电统一黑色实线（graphwidget · paintTo）：原充电段使用 Blitbuffer.COLOR_GRAY，在 KPW3 黑白墨水屏上灰色线条过淡、不美观。改为充放电均使用 COLOR_BLACK 实心线，对比度一致、清晰。点击详情仍显示"充电中/放电中"文字状态（不受影响）。
  • 修复折线"断裂"（graphwidget · paintTo）：移除 v1.0.3 引入的"相邻采样间隔 > 6h 断开连线"逻辑（GAP_THRESHOLD）。该逻辑在设备关停/长时间无采样（如休眠超 6 小时）时不绘制相邻两点之间的连线，导致折线在中间"缺一段"，观感像线条消失/断裂。现改为连续绘制所有相邻点之间的连线。
  • 图例同步（graphwidget · init）：底部图例由"放电(黑) / 充电(灰)"两条改为单一"电量曲线"，与"充放电统一黑色"一致，避免文字与图形不符、且保持纯 ASCII 无字形风险。
  • 校验：LuaJIT loadfile 对 graphwidget.lua 编译通过；其余模块未改动。仍待 KPW3 真机验证（本环境无 KOReader 运行时）。

注：连续绘制后，若设备关停数日，折线会以直线段跨接这段空缺——这是为消除"断裂"观感的有意取舍；若你更希望空缺处明确留白，可改回按阈值断线（阈值可调）。

本次修改（v1.0.5 — 修复「关于」点击崩溃）

⑭ 修复主菜单「关于」点击即崩溃
  • 现象：点击主插件菜单「关于」KOReader 立即崩溃退出。

  • 修复：在 main.lua 顶部 require 列表补 local InfoMessage = require("ui/widget/infomessage")（仅此一行）。
  • 校验：LuaJIT loadfile 对 main.lua 编译通过。教训此类"漏 require 导致全局 nil"属运行期崩溃，LuaJIT 语法编译无法捕获，必须依赖 crash.log 的栈定位——今后新增 UI 弹窗需核对所用 widget 是否已在文件中 require。

动机（为什么合并）

两插件同属电量监控范畴且功能互补不冗余：batterygraph 给"电量怎么走"（连续曲线），sleepwaketracker 给"看书掉多少/待机掉多少"（分段统计）。二者原有"伪整合"但存在脆弱点——sleepwaketracker 用 dofile 硬编码拼路径跨插件加载 graphwidget.lua，一旦以 zip 形态分发，该路径不存在会静默失效。

合并后：单一插件、单一菜单、进程内模块调用，彻底消除 dofile 雷，并兼容目录与 zip 两种形态。数据文件保持原路径（settings/battery_graph.lua 与 <data_dir>/sleepwaketracker/），历史数据无损。
