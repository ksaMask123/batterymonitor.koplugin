二、性能与内存验收（硬性）

条目检查方法与证据判定说明
2.1 禁止同步阻塞（网络/磁盘/重算异步） 本插件纯本地、无网络 → 网络项 N/A。磁盘：sleepwake_ctrl.lua:367 readAllEvents 同步 io.open 全量逐行解析 + table.sort（单文件上限 1MB）；有 cached_events 缓存（:368 命中即返），但缓存失效 6 处（:31/:225/:270/:309/:970/:988）后，菜单触发的重载会在单核上同步读整份日志 → 大日志/365 天数据有卡顿风险。采样与刷新均走 UIManager:scheduleIn（:301/:332/:333/:789/:1209） ⚠缓存缓解，非全异步
2.2 防抖（翻页/高亮/进度等频繁事件） grep 无 onTurnPage/高亮/阅读进度监听；记录为节流式（min_sample_interval=300s、min_new_point_interval=3600s），非高频写入。无频繁事件需防抖合并 ⬜本插件不监听此类事件
2.3 懒加载（非核心点击才载） graphwidget 仅绘图时 require（:310）；关于/帮助/配置均在回调内 :new，启动仅核心必要模块 ✓达标
2.4 内存释放（大块数据置 nil + 主动 GC） grep 全插件 无任何 collectgarbage 调用；cached_events 6 处置 nil 仅为懒失效缓存，非「用毕显式释放 + 主动回收」；readAllEvents 构造的全量 events 表（堆）除缓存复用外未主动释放 ❌缺主动 GC

极端情况策略（本插件真实场景，非"弱网同步"——本插件无网络）

  • 大日志 + 菜单快速点击：readAllEvents 同步整读 1MB 日志（单核可能卡顿）→ 现状靠 cached_events 缓存规避二次读；整改建议：菜单首读改 UIManager:scheduleIn 异步 + 加载态提示。
  • 唤醒电量 = BATTERY_UNKNOWN(-1) / 非法：readAllEvents 已过滤 bat >= -1 and <= 100，非法行记 warn 并写回清洗（:404-407）。
  • 365 天数据累积：max_history_days=365 截断；max_log_size=1MB + max_backup_count=3 轮转（:198）。
  • 系统时间回拨：table.sort 按 timestamp 升序；recordPoint 用「状态变化/电量变化/时间间隔」三条件去重，回拨不产生倒序崩溃。
  • FM/Reader 双实例并发：recordPoint 落盘前重读磁盘历史合并（changelog 段 ⑭），避免互相覆盖。
